# ESPM — Explainable Security Incident Prioritization Module (PoC v0.2)

PoC к дипломному проекту **«Development of an Explainable Security Incident Prioritization Module for SIEM Based on Asset Context and Event Sequence Analysis»**.

**Авторы и распределение разработки прототипа:**
- **Сабыр (Sabyr):** Модуль обогащения контекстом активов (`classify_asset`, Location-Aware CMDB и расчёт `criticality` / `vulnerability (EPSS)` / `centrality`), аддитивный движок объяснимого скоринга (`ESPMScorer`), генератор машинно-читаемых объяснений (`demo_explanation.py`), графики (`generate_figures.py`) и интерактивный веб-дашборд SOC-аналитика (`dashboard.html`).
- **Владимир (Vladimir):** Модуль потокового парсинга и нормализации алертов Wazuh (`parse_wazuh_jsonl`), мэппинг правил детекции на тактики MITRE ATT&CK v20 (`attack_phase`), алгоритм последовательностного анализа с $O(1)$ временными корзинами и памятью стадий атаки (`chain_evidence`, `attack_progression`), стенд честной оценки метрик и абляций (`evaluate.py`) и модульные тесты (`test_espm.py`).

### Результаты Ablation Study (вклад отдельных компонентов ESPM по 8 сценариям)

- **ESPM v0.2 (Полная модель):** Macro AUROC = **0.9669**, Macro AP = **0.9475**, Macro P@10% = **87.3%**, медианный ранг захвата root = **#1.5** (`#1.0–#3.5` в 7 из 8 сценариев).
- **ESPM без контекста актива (`espm_no_asset`):** Macro AUROC падает до `0.9640` (на шумном `santos` с `0.930` до `0.914`), а медианный ранг захвата root ухудшается с `#1.5` до `#6.3` (на `shaw` с `#1.0` до `#10.0`).
- **ESPM без памяти последовательности (`espm_no_sequence`):** Macro AP падает до `0.9421` (на `santos` AUROC падает с `0.930` до `0.916`), а на `russellmitchell` и `fox` ранг захвата root проседает с `#2.0 / #3.5` до `#14.0 / #17.0`.
- **Почему в слепом сценарии `wheeler` ранг захвата root равен `#310` (Топ 0.05% из 603 939 алертов)?** В сценарии `wheeler` атакующий выждал **35 644 секунды (~10 часов)** между загрузкой веб-шелла и запуском `reverse_shell`/`sudo`, что превышает наш 1-часовой горизонт памяти `chain_window_s = 3600 с`. Но даже без активного буста `chain_evidence` комбинация фазы `Privilege Escalation (0.95)` и критичности `intranet-server (0.95)` вывела событие `level=3` на **#310 место из 603 939 алертов**, тогда как у RBA оно на **#421 283 месте**, а у Severity — на **#488 354 месте**!
